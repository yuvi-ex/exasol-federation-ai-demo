# Datasets

Everything the demo loads, so a new setup needs no export step. `python -m setup.setup` uses these files.

| File | Rows | Used for | Loaded into |
|---|---|---|---|
| `support_tickets.csv` | 5,000 | What customers say: the vector search and the ML model | Exasol table `DEMO_DATA.SUPPORT_TICKETS`, then Qdrant Cloud |
| `lake/lineitem/ship_year=1992.parquet` … `ship_year=1998.parquet` (7 files, ~125 MB) | 6,001,215 | What shipped: the S3 data lake | Your S3 bucket under `lake/lineitem/`, read in place by Exasol |

Customers and orders are **not** here: the demo reads them live from Snowflake, where every account has them in
`SNOWFLAKE_SAMPLE_DATA.TPCH_SF1` (see `setup/snowflake_setup.sql`).

## support_tickets.csv

Synthetic B2B support tickets, generated by [`setup/data/gen_tickets.py`](../setup/data/gen_tickets.py) with a fixed
seed, so running the generator reproduces this file exactly.

| Column | Meaning |
|---|---|
| `TICKET_ID` | 1 to 5,000 |
| `C_CUSTKEY` | A real TPC-H customer key (customers that have orders), so tickets join to Snowflake data |
| `CREATED_DATE` | 1997-01-01 to 1998-07-29, inside the TPC-H order period |
| `CHANNEL` | email, portal, phone transcript, account manager note, chat |
| `CATEGORY` | Hidden label: late_delivery, damaged, wrong_item, billing, quality, praise, account |
| `CHURN_INTENT` | Hidden label: 1 when the ticket threatens to leave (about 21% of tickets) |
| `TICKET_TEXT` | The ticket. Phrasing avoids each category's obvious keyword, so search has to work by meaning |

`CATEGORY` and `CHURN_INTENT` are ground truth for checking the search and training the model; the search never sees
them. Churn is expressed through a few fixed phrases, which is why the model scores near 100%: treat that as a
property of synthetic data, not a result.

## lake/lineitem/*.parquet

TPC-H `LINEITEM` at scale factor 1, one file per ship year, with one extra column, `L_DAYS_LATE`
(receipt date minus commit date). Written with an explicit, stable schema:

| Column | Type |
|---|---|
| `L_ORDERKEY`, `L_PARTKEY`, `L_SUPPKEY`, `L_LINENUMBER`, `L_DAYS_LATE` | int64 |
| `L_QUANTITY`, `L_EXTENDEDPRICE`, `L_DISCOUNT`, `L_TAX` | decimal(15,2) |
| `L_SHIPDATE`, `L_COMMITDATE`, `L_RECEIPTDATE` | date32 |
| `L_RETURNFLAG`, `L_LINESTATUS`, `L_SHIPINSTRUCT`, `L_SHIPMODE` | string |

TPC-H data is synthetic benchmark data produced by the TPC-H data generator. TPC-H is a trademark of the Transaction
Processing Performance Council; nothing in this demo is a TPC-H benchmark result. TPC-H dates are uniform by design,
so late-shipment rates look alike everywhere: they prove the joins, not a business finding.
